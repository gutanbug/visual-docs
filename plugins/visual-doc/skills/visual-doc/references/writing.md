# 문체

레퍼런스 문서의 말투를 따른다. 원문이 개조식·영문이어도 페이지에서는 아래처럼 바꾼다 (고유명사·코드·명령은 그대로).

## 규칙

- **해요체, 한 문장 한 생각.** "~합니다", "~함", "~임" 을 쓰지 않는다.
- **제목은 주장이다.** `아키텍처` 가 아니라 `요청은 받기만 하고, 보내기는 워커가 해요`. 주제어는 `eyebrow` 에 둔다.
- **h1** 은 두세 줄. 첫 줄은 상황·행동, `<em>` 구절은 얻는 것, 끝은 짧게. 예: `팀 자료를 올리면 / <em>Claude가 wiki로</em> 정리해요`.
- **lead** 는 두세 문장으로 무엇을·어떻게·어디서.
- **eyebrow** 는 1~2 단어 명사 (`흐름`, `기능`, `구조`, `결정`, `일정`).
- **타일 설명(`p.d`)** 은 2~3문장, 기능이 사용자에게 주는 결과부터.
- **흐름 단계(`b`)** 는 2~5자 동사구, **설명(`.d`)** 은 한 줄 (20자 안팎).
- **배지 문구** 는 2~4자 (`확정`, `결정 필요`, `채택`, `보류`, `1위`, `충돌`).
- **숫자** 는 단위를 `<small>` 로 분리하고 원문 표기를 바꾸지 않는다. 시각·버전·ID 는 mono.
- **마무리(`.start`)** 제목은 권유형 (`지금 바로 써 보세요`, `다음 리뷰 전에 정해 주세요`).

## 바꾸기 예

| 원문 | 페이지 |
|---|---|
| 알림 발송 실패 시 재시도 미지원 | 실패한 알림을 다시 보내지 않아요 |
| 3단계 승인 프로세스 도입 | 세 번 확인한 자료만 반영돼요 |
| API Gateway 경유 인증 처리 | 인증은 게이트웨이가 먼저 해요 |
| TBD | `결정 필요` 배지 (내용을 지어내지 않는다) |

## 쓰지 않는 것

- 원문에 없는 효과·수치 과장 (`획기적으로`, `10배`)
- 느낌표, 이모지, 물음표로 끝나는 제목 남발 (FAQ 제외)
- 한 섹션에 문단 두 개 이상 — 길면 컴포넌트로 쪼갠다
